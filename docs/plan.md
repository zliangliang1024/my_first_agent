## 🎯 Phase 1：健壮核心（1 周）

**目标**：让 Agent 从「能跑」到「不会崩、体验流畅」。

### 1.1 流式输出

- **技能**：SSE 解析、`reqwest` stream、channel 增量事件
- **产出**：DeepSeek 回复逐字显示
- **学到**：异步流处理、背压、事件驱动 UI

### 1.2 取消机制

- **技能**：`CancellationToken`、`tokio::select!`
- **产出**：发送按钮旁加「停止」，能中断生成和工具执行
- **学到**：异步任务的协作式取消

### 1.3 错误重试与降级

- **技能**：指数退避、`tokio-retry`
- **产出**：网络抖动自动重试 2~3 次，MCP 崩溃自动重启
- **学到**：容错设计、幂等性

### 1.4 请求超时与心跳

- **技能**：`tokio::time::timeout`
- **产出**：DeepSeek 超过 60s 无响应自动失败；MCP 子进程存活检测
- **学到**：超时策略、健康检查

**阶段产出**：一个不会卡死、能中断、能自愈的 Agent。

## 🧠 Phase 2：记忆系统（1 周）

**目标**：让 Agent 记得住、聊得久。

### 2.1 会话持久化

- **技能**：`serde_json`、文件 IO、多会话管理
- **产出**：
  - 会话自动存到 `sessions/*.json`
  - 启动时恢复上次会话
  - 侧边栏：新建 / 切换 / 重命名 / 删除会话
- **学到**：状态快照、增量保存、文件锁

### 2.2 上下文长度管理

- **技能**：Token 计数、摘要压缩、滑动窗口
- **产出**：
  - 接近上限时自动摘要早期对话
  - 状态栏显示当前 token 占用
- **学到**：上下文工程（Context Engineering）核心技能

### 2.3 Token 与成本统计

- **技能**：解析 `usage` 字段、累计统计
- **产出**：状态栏显示「本次 xx tokens · ¥x.xx ｜ 累计 ¥x.xx」
- **学到**：成本可观测性

**阶段产出**：一个能长期使用、成本透明的 Agent。

## 🛡️ Phase 3：安全与权限（1 周）

**目标**：让 Agent 不会闯祸，人机边界清晰。

### 3.1 工具调用人工确认

- **技能**：`oneshot` channel、审批弹窗、状态机
- **产出**：
  - 危险工具（删除、sudo、写入）弹出确认框
  - 显示工具名、参数、风险提示
  - 「允许一次 / 允许本次会话 / 拒绝」
- **学到**：HITL（Human-in-the-loop）设计

### 3.2 工具风险分级

- **技能**：策略模式（Policy Pattern）
- **产出**：
  - 定义 `RiskLevel`：Low / Medium / High
  - 每个工具映射风险等级
  - 按等级决定是否审批
- **学到**：最小权限原则、安全策略配置

### 3.3 操作审计日志

- **技能**：结构化日志、`tracing`
- **产出**：所有工具调用记录到 `audit.log`（时间、工具、参数、结果、审批人）
- **学到**：合规审计、事后追溯

**阶段产出**：一个让人放心用的 Agent。

## 🛠️ Phase 4：技能系统（1 周）

**目标**：把 Agent 从「通用工具调用器」升级为「会 SOP 的专业助手」。

### 4.1 AGENTS.md 加载

- **技能**：Markdown 解析、Prompt 注入
- **产出**：启动时读取项目根目录的 `AGENTS.md`，注入 system prompt
- **学到**：Agent 人格定义、项目级规则

### 4.2 SKILL.md 技能库

- **技能**：YAML frontmatter 解析、渐进式披露
- **产出**：
  - `skills/<name>/SKILL.md` 目录结构
  - 启动时扫描，frontmatter 索引注入 prompt
  - Agent 判断需要时，通过工具读取完整 SKILL.md
- **学到**：Agent Skills 规范、Prompt 分层

### 4.3 编写 3~5 个实用技能

- **示例技能**：
  - `server-diagnostics`：服务器健康检查 SOP
  - `code-review`：代码审查清单
  - `incident-response`：故障响应流程
  - `daily-report`：日报生成
- **学到**：将领域知识工程化

**阶段产出**：一个有领域知识、行为可控的 Agent。

## 🔌 Phase 5：扩展工具边界（1 周）

**目标**：从单 MCP 走向多工具生态。

### 5.1 多 MCP Server 管理

- **技能**：`HashMap<String, McpClient>`、工具前缀路由
- **产出**：
  - 支持配置多个 MCP Server
  - 工具名加前缀 `server__tool`
  - 按前缀路由调用
- **学到**：多源工具聚合、命名空间管理

### 5.2 MCP 配置热重载

- **技能**：文件监听、`notify` crate
- **产出**：修改 `config.json` 后自动重连 MCP
- **学到**：配置驱动的运行时

### 5.3 自定义 Rust 工具

- **技能**：实现本地 tool（不走 MCP）
- **示例工具**：
  - `get_current_time`：获取当前时间
  - `read_local_file`：读取本地文件
  - `search_web`：调用搜索 API
- **学到**：MCP 工具 vs 本地工具的边界

**阶段产出**：一个能接入任意工具源的 Agent。

## 📚 Phase 6：长期记忆与 RAG（1~2 周）

**目标**：让 Agent 拥有跨会话的语义记忆。

### 6.1 集成 LanceDB

- **技能**：向量数据库、Arrow Schema
- **产出**：本地 `memory.lance` 存储历史对话的向量
- **学到**：嵌入式向量库的使用

### 6.2 Embedding 接入

- **技能**：调用 Embedding API（DeepSeek 或本地模型）
- **产出**：每条消息向量化后存入 LanceDB
- **学到**：向量化、维度、余弦相似度

### 6.3 语义检索工具

- **技能**：Top-K 检索、相似度阈值
- **产出**：新增 `recall_memory` 工具，Agent 可主动检索历史
- **学到**：RAG 的召回环节

### 6.4 自动记忆注入（可选）

- **技能**：每次用户输入前自动检索相关记忆
- **产出**：相关历史自动注入 context
- **学到**：RAG 的完整链路

**阶段产出**：一个记得住过去、跨会话有连续性的 Agent。

## 🎯 学习节奏建议

### 每周节奏（推荐）

```
周一~周二：读文档 + 设计
周三~周四：写代码
周五：测试 + 复盘 + 写笔记
周末：整理成本阶段的知识点
```

### 里程碑检查点

每完成一个阶段，问自己三个问题：

1. **能用吗？** —— 功能是否真的改善了体验？
2. **懂了吗？** —— 能不能给别人讲清楚这段代码的原理？
3. **能改吗？** —— 需求变了，能否快速调整？

### 关键原则

- **不要抄框架** —— 自己实现一遍，理解每个设计决策的原因
- **不要贪多** —— 每个阶段做完整，比同时开 5 个方向强
- **保持可运行** —— 任何时候 `cargo run` 都应该能跑
- **写下你的设计** —— 每个 Phase 结束写一篇 short note，是面试谈资
